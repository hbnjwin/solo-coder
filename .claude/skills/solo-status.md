# solo-status

统计当前所有题目的交付进度、轮次分布、单轮占比，帮助规划后续出题策略。

## 使用方式

```
/solo-status
```

## 执行步骤

### 1. 收集数据

- 读取 `auto-solo-fill-tool` 的数据文件（通过 Tauri 存储的 JSON）
- 扫描 `projects/trae-solo/` 下的所有项目目录
- 检查 GitHub 仓库的分支状态
- 读取 `docs/require/题库列表.md` 获取题目清单

### 2. 统计维度

输出以下统计信息：

```

| 指标 | 数值 |
|------|------|
| 题库总题数 | N |
| 已交付题目 | M |
| 进行中题目 | K |
| 未开始题目 | J |

## 轮次分布

| 轮次数 | 题目数 | 占比 | 状态 |
|--------|--------|------|------|
| 1 轮完成 | X | X% | ⚠️ 需 < 8% |
| 2 轮完成 | X | X% | ✅ |
| 3 轮完成 | X | X% | ✅ |
| 4 轮完成 | X | X% | ✅ |
| 5 轮完成 | X | X% | ✅ |
| 未完成 | X | X% | — |

| 领域 | 题目数 | 是否必须 |
|------|--------|----------|

- [如果单轮占比接近 8%，给出警告]
- [如果某个必须覆盖的领域为 0，给出提示]
- [如果题目难度过于集中，给出建议]
```

### 3. 出题建议

基于当前统计，给出建议：
- 如果单轮占比过高：建议下一题设计为需要 2-3 轮的中等复杂度
- 如果某领域缺失：建议补充该领域的题目
- 如果难度分布不均：建议调整

## 数据来源

优先级：
1. `auto-solo-fill-tool` 的持久化数据（最准确）
2. `projects/trae-solo/` 目录结构 + git 分支状态
3. `docs/require/题库列表.md` 的题目清单
