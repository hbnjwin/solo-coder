# 飞书表格提交字段说明

## 交付字段总览

| 字段                       | 是否必填    | 填写说明                                                                       |
| -------------------------- | ----------- | ------------------------------------------------------------------------------ |
| Trae Session ID            | ✅ 必填     | 所标注轮次的 Session ID，双击对话界面对应轮次 Agent 消息的 Trae 宝头像即可复制 |
| User Prompt                | ✅ 必填     | 所标注轮次的 User Query，填写本轮对话的实际提示词                              |
| 任务类型                   | ✅ 必填     | 见下方选项（根据当前轮次内容判断）                                             |
| 业务领域                   | ✅ 必填     | 见下方选项                                                                     |
| 修改范围                   | ✅ 必填     | 见下方选项                                                                     |
| 任务难度                   | ✅ 必填     | 见下方选项                                                                     |
| 任务是否完成               | ✅ 必填     | 结合第一轮整体需求及所有轮次累加需求综合判定                                   |
| 产物及过程是否满意         | ✅ 必填     | 过程优先级最高，看完过程再看产物                                               |
| 不满意原因                 | ⚠️ 条件必填 | 产物及过程不满意时必填，需分别说明产物和过程的不满意原因                       |
| GitHub 地址                | ✅ 必填     | 对应题目的 GitHub 仓库地址                                                     |
| 截图（产物/运行结果/对话） | ✅ 必填     | 日志轨迹超长时可粘贴进 txt 后上传到截图字段                                    |
| 日志轨迹                   | ✅ 必填     | 本轮完整执行日志；超长时粘贴进 txt 附件上传到截图字段                          |
| AI 质检                    | —           | 按钮，点击进行初审                                                             |
| 过程分析                   | —           | 按钮，点击进行 AI 过程轨迹分析（仅供参考）                                     |

## 选项定义

### 任务类型

| 选项         | 说明                                         |
| ------------ | -------------------------------------------- |
| Bug 修复     | 逻辑修复、报错排查、安全漏洞修补             |
| 0-1 代码生成 | 基于 PRD 或自然语言描述的新项目/完整模块构建 |
| Feature 迭代 | 在已有功能基础上的平滑扩展                   |
| 代码理解     | 解释逻辑、寻找潜在风险、回答技术细节         |
| 代码重构     | 性能优化、可读性提升、解耦                   |
| 工程化       | 环境配置、依赖管理、CI/CD 相关               |
| 代码测试     | 单测、集成测试等                             |

> 任务类型根据**当前轮次**内容判断，而非整个对话。例如第一轮是"代码生成"，第二轮修复第一轮的错误则应标记为"Bug 修复"。

### 业务领域

| 分类             | 选项                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------ |
| 大前端与服务端类 | 纯后端 API 服务、Web 前端、全栈 Web 应用、垂直业务                                   |
| 前沿技术         | 游戏开发、数据分析与可视化（如 Dash/Streamlit）、3D/交互可视化、AI/ML 应用、科学计算 |
| 端侧与基础工具   | 命令行工具、桌面应用（含 GUI）、自动化与工具脚本                                     |

> 必须覆盖**大前端与服务端**类任务，其他类型不做硬性限制。

### 修改范围

| 选项         | 说明                                                                         |
| ------------ | ---------------------------------------------------------------------------- |
| 无需修改     | 代码理解等无需代码生成的任务；所有不产生 diff 的 session（包括生成 md 文件） |
| 单文件       | 局部逻辑修改                                                                 |
| 模块内多文件 | 涉及同一模块内的接口定义与实现协同                                           |
| 跨模块多文件 | 涉及多个逻辑单元的调用链修改                                                 |
| 跨系统多模块 | 涉及前后端联调、跨服务调用、或数据库-后端的垂直改动                          |

### 任务难度

| 选项 |
| ---- |
| 一般 |
| 较难 |
| 困难 |
